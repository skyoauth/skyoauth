# SkyOAuth — Detailed design, implementation tasks, and release gates

> **Status:** proposed implementation plan. Paired with [skyoauth-design.md](skyoauth-design.md). All authentication checkboxes remain **unchecked**. The landed service/health-client scaffold is not an implementation of these security contracts.

## 0. Delivery principles

The central outcomes are **secretless GitHub Actions → protected cluster API WIF** and **zero-client-change / zero-WIF-reset human IdP migration**. Browser sessions, gateway integration, a **TypeScript library for SPAs** and a **reusable Rust client crate for CLI applications** are all required before v0.1. A Node-only library or a repository-local Rust executable alone does not satisfy the client requirements.

- Human migration may require reauthentication, not changes to client/backend binaries, packages, settings or deployments. Preserve every source kind, keyset, binding, grant, audience assignment, client/origin registration and effective WIF decision.
- Envoy is the application data plane. SkyOAuth processes bounded authentication/authorization metadata, never uploads, downloads or stream bodies.
- The stable issuer and signing keys are independent of the human IdP. Explicit private credential profiles separate WIF access, human CLI access and gateway-only human-session assertions.
- Instance-owned resource-server/audience authority bounds tenant policy; services a workload acts as are not resource servers or policy-check callers. Canonical backend tenant mapping and RBAC remain mandatory.
- Direct workload and attributed service delegation are required. Active true impersonation is outside v0.1; retain only disabled/reapproval-required policy preservation. Its future activation subsystem is deferred, not a release prerequisite.
- Standard RFC 8693 direct exchange and the single-proof service-delegation extension are distinguished. No incomplete RFC 9068 `at+jwt` claim: use the private types defined in design §6.
- The only active-provider write path is an authorized switch transaction with epoch invalidation. PATCH/import/config reload cannot bypass it.
- Operator/recovery/reviewer keys are privileged operational trust anchors, not static application API secrets. No SPIRE/sidecar/cloud STS dependency is required.
- Both client profiles have package, real-runtime and migration tests. Share wire/error fixtures, not browser-unsafe token APIs or server dependencies.
- Required M4 native refresh keeps access credentials at a maximum 300-second lifetime without a browser prompt on every renewal; persistent refresh remains a sensitive revocable credential, not a static API key.
- Every security requirement needs positive and negative tests; the tasks below do not claim they are already implemented.

**Workload-first sequence:** specify the complete logical model in M0, implement workload authority in **M1a**, and let **M2 WIF proceed after M1a**. Human authority/state is **M1b**, parallelizable with M2 but required before M3. Do not require human tables, browser/native UX or a tenant-management UI before the first usable workload slice. Full v0.1 still requires both libraries, human migration and all applicable security gates; explicit tenant/audience isolation is retained. Design §1.3 records this scope decision.

Server boundaries can start as modules; extract crates for dependency isolation or reuse, not directory count. The Rust client must not depend on the service, PostgreSQL, operator internals or frontend assets. npm `@skyoauth/client` and Cargo `skyoauth-client` are intentionally parallel names in different registries; Rust imports `skyoauth_client`. Documentation and examples identify the language/distribution explicitly.

**M1a `operator/` publishes `skyoauth-operator`**, a portable Linux/macOS/Windows private mTLS client and recovery-challenge signer, independent of server/database dependencies and M4 native OAuth. The recovery signature is verified inside the library's `restore_operator` (Ed25519 via `ed25519-dalek`, weak keys refused; docs/proposals/recovery-verified-response.md); the existing service binary retains only the deployment-local bootstrap and recovery transport. Recovery challenges cross an independently authorized local channel; private operator/recovery keys remain on the workstation or hardware signer, never copied into a pod. M1b adds human provisioning/transition commands to the same operator client. `cli/` remains the separate M4 application/reference consumer.

The existing TypeScript arbitrary-baseUrl `health()` helper is unauthenticated bootstrap functionality. It cannot define the future authenticated session transport's origin boundary. Keep `@skyoauth/client` as the browser core rather than creating competing `packages/browser` or `crates/client` homes. Future TypeScript workload helpers are additional nonbrowser surfaces. The M3 `skyoauth-service route-control` process is a separate least-privilege deployment of the route_control module, not part of either client library.

Implementation PRs adding/moving modules, workspace members or package entry points update manifests/exports, lockfiles, CI paths/build/test/coverage, package-consumer examples and README together. Preserve the bootstrap's docs-only skip behavior; a skipped job is not a passed runtime test.

## 2. Public and operator contract — specification tasks

### T00 — Protocol and threat model (M0)

- [x] **T00.1** Freeze public issuer/token/JWKS, app-origin auth, issuer-native callback/confirmation/refresh/revoke, private gateway/live-check/session-recheck/session-close/internal-key, scoped route preparation/result/list/read/claim/transition/observation and operator approval boundaries. Cleanup/revocation must not depend on the application route gate. Contract: [contracts/public-api.md](contracts/public-api.md).
- [x] **T00.2** Version errors, no-store, cancellation and non-enumerating failures. Separate 401 authentication, 403 authorization, 429 per-session too_many_open_streams/rate_limited and 503 shared stream_capacity_unavailable/route_configuration_unavailable (Connect unavailable). Define finite retry budgets and the one delayed per-session recovery retry; never a login prompt for infrastructure/capacity or mutation replay. Contract: [contracts/errors-retry.md](contracts/errors-retry.md).
- [x] **T00.3** Specify exact protected types `skyoauth-access+jwt` and `skyoauth-internal+jwt`, signed profile/version and required WIF/human_cli/human_session claim sets. Reject profile/ingress mismatches and ID tokens; do not advertise RFC 9068 compliance or emit `at+jwt`. Contract: [contracts/token-profiles.md](contracts/token-profiles.md).
- [x] **T00.4** Freeze issuer, audience registry, principal kinds, scopes, claim namespace and constraints. WIF uses explicit allowlists; human profiles explicitly use backend_rbac mode with mandatory canonical tenant/scope/RBAC checks. Persist action-to-scope/profile/resource rules; unknown modes/fields/versions deny. Contract: [contracts/identity-registry.md](contracts/identity-registry.md).
- [x] **T00.5** Freeze exact digest binding and all-route credential containment. Every enrolled-host route, including the issuer host, public/health/static routes with no Check and non-exempt SkyOAuth endpoints, gets ordinary HTTPRoute RequestHeaderModifier removal of Cookie/X-SkyOAuth-CSRF after any required auth and ResponseHeaderModifier removal of every Set-Cookie (OQ-GW-3, OQ-GW-12). The only exceptions are the seven fixed exempt SkyOAuth cookie endpoints and each exact registered per-provider issuer callback path `/oauth/callback/{provider_id}` (OQ-TM-4). Pin exact backend-identity-bound auth exemptions and actual filter order, not an unspecified selective-cookie filter. Define security-revision-bound recovery, mode-bound registry-only versus gateway activation, bounded apply timeout, cancel/revoke roles and exact abort/supersession authority, and protected-scope projection including shared listener dependencies but excluding disjoint virtual hosts and only proven-inert filters. Include controller-token/mTLS-key sandbox denial tests, explicitly validated Secret-substitution/dependency profiles, renewable protected-listener profile/writer/overlap/recovery fixtures, temporary-versus-terminal material failure outcomes and staged exact-mode reference rotation and effective-filter override/order fixtures. M3 isolated controller preparation computes expected xDS before approval; M1b only supplies pending/result contracts. Freeze what is pinned and how (EG/egctl/Envoy/bootstrap as one set, complete inputs, adapter fixtures) and the management GET shape (per-target resource/mask, response-size and request-time bounds); the literal version pair, artifact digests, masks and bounds are fixed in T32.3/T50.4 against a tested pair (OQ-GW-1, OQ-GW-2). No caller hash or whole-shared-dump shortcut. Contract: [contracts/gateway-containment.md](contracts/gateway-containment.md).
- [x] **T00.6** Specify session/flow/code/epoch/restore lifetimes, access <=300s/internal evidence <=30s and refresh defaults 12h/1h with explicit 7d/24h ceilings and no existing-family extension. Browser leases default/critical <=15s, opted-in noncritical <=300s/context <=1h. Route polling <=10s, stale alert 30s, equivalent verified deployment evidence <=300s from collection start; gateway apply/mismatch has no allowance. Registry-only activation preserves sample ages and cannot extend the deadline. Planned apply returns unavailable for unchanged contexts with no lease extension; changed dependencies deny. Record full-origin apply interruption and cleanup independence in ADR-010/ADR-020. Apply timeout (default120s/ceiling300s), forward expiry and separately approved finite abort_until have distinct execution meanings and survive takeover; neither stale evidence nor compensation extends a stream lease. TLS renewal overlap is independently bounded (default120s/ceiling300s), capped by material validity, never a reset of observation/lease cutoffs. Contract: [contracts/lifetimes.md](contracts/lifetimes.md).

### Exchange selection and scope

Require one generated source ID, generated grant ID and exact registered audience. Load source/grant only as candidates; require same tenant, then verify the proof at that source. Filter matching bindings by **the selected grant's actor and nonempty allowed_binding_ids**. At least one eligible enabled binding must match. Bindings for other actors do not cause ambiguity or confer access. Bindings are identity-only in v0.1; multiple eligible matches choose a stable ID for provenance, never union permissions. Configuration rejects cross-actor/cross-tenant binding references.

Direct RFC exchange accepts subject_token/type=jwt and a direct grant, returns workload sub, rejects actor_token. The private service-delegation grant accepts actor_token/type=jwt and a delegated grant, returns configured service sub plus workload act, rejects subject_token. No requested subject/target/mode override or dynamic verifier selection.

Omitted scope uses only explicit nonempty allowed default_scopes; otherwise invalid_scope. Explicit empty/excessive scopes, unsupported resource/requested token types, duplicates or profile mismatch deny (a repeated token inside one `scope` value: open question OQ-IR-11). Return access_token, Bearer token_type, expires_in, explicit scope and `issued_token_type=urn:ietf:params:oauth:token-type:access_token`, no-store, never WIF refresh. The design's exported example uses **post-create generated IDs**, not operator-chosen global identifiers.

**Ownership:** ResourceServer/audience namespace, ResourceServerChecker/Action and origin ownership enrollment are instance authority; AudienceTenantAssignment grants named tenants bounded issuance rights. Composite same-tenant references protect all tenant-owned objects and their immutable versions. ServiceIdentity.id references a svc principal and contains no checker credentials. Direct grants require null target; delegated grants require a same-tenant service. ApplicationOrigin has globally unique canonical origin, assigned rather than claimed by tenant admins. OAuth client_id is globally unique and generated, so issuer-native authorization deterministically resolves its tenant. HumanAccessPolicy has exactly one client/origin consumer and one registered audience, unique per consumer/audience. The active bundle pins the origin/route versions used to resolve a cookie request; exact paths beat longest segment-prefix paths for the method, ties reject and disabled winners deny rather than falling back. Canonical request/route matching and no-rewrite rules are normative in design §4.1.

**Route preparation, approval and recovery:** origin/route/bundle versions are immutable; active_version_id alone selects live registry pins. client_admin requests a route_bundle_prepare AdministrativeOperation containing the immutable source snapshot, expected active generation, affected-parent security revisions, required activation_mode (registry_only or gateway_apply) and explicit recovery intent. M1b persists these contracts; M3's isolated controller worker runs the pinned translator, computes the input digest (= translator_input_digest, SHA-256 over RFC 8785 JCS; OQ-GW-7) and submits its authenticated bound result before the service creates a completed RouteBundleVersion. Pending/failed operations and caller digests are not approvable. Instance security_admin's separate expiring route_bundle_approval binds the finalized plan, activation_mode and security_preconditions/reenable_targets. Finalization checks registry_only equivalence to the captured deployment_version_id; mode changes require a new preparation and approval. A gateway_apply version retains an exact abort_plan of prior registry/deployment pins and scoped prior resource values/absence. Its approval immutable_plan includes a finite abort_until later than the forward expires_at within an instance maximum; both are displayed, never inferred by the controller. Preparation-result, begin and final activation recheck relevant preconditions; all role/approval/security checks at activation share the pin-change transaction. Exact result retries are idempotent, contradictory results reject. Gateway-apply input/version/approval binds apply_timeout_seconds (default 120, positive, <= instance-configurable ceiling hard-capped at 300; OQ-LT-6); begin persists apply_deadline=min(begun_at+timeout, expires_at). RouteBundleAttempt retains the original deadline, revision, reason and journal through claims/restarts; runtime and attempt transitions share one transaction. No forward activation at/after the deadline. A durable service reconciler checks deadlines at least every 10s; the scoped owner aborts on terminal apply/programming error or deadline without waiting for approval expiry. Transient failures may retry within that bound.

Tenant client_admin in scope or instance security_admin may POST attempts/{attempt}/cancel: audited route_bundle_cancel plus expected attempt revision moves the current applying attempt to abort_required, preserving compensation. Exact retries while abort_required/aborting cannot extend deadlines; old IDs cannot affect successors. Instance security_admin alone may POST approvals/{approval}/revoke: route_bundle_approval_revoke atomically records revoked_at/revocation_operation_id and advances approval revision without changing immutable_plan. It blocks unbegun execution and both write directions of an unfinished attempt, marking recovery_required. Revocation after completed activation does not roll back that deployment; independent security disable handles incident denial. Cancel/revoke/activation races serialize.

security_preconditions maps every pinned/affected stable origin/route parent to its captured security_revision; reenable_targets explicitly lists typed parent IDs, expected disabled revisions and recovery reasons. A later disable advances the revision and invalidates its forward authorization (not already-approved bounded compensation of a begun attempt), including the 09:00 approval / 09:20 disable / 09:30 apply case. Activation may clear only explicitly approved targets and increments their revisions atomically; all others retain their status. The only exception is an origin whose security_reason is still not_enrolled: its first approved gateway_apply enables it without a target by CAS on security_revision (T14.5). An incident disable sets security_reason incident and is cleared only as a named target. configured_status=enabled in a pinned route version is insufficient while either parent is security-disabled, and clearing the security veto cannot override configured_status=disabled. No fallback, replacement-ID/unpin bypass or rollback restoration of newer security state. Security revisions are execution preconditions and current credential dependencies, not a bundle-wide runtime equality that revokes unrelated routes. No direct PATCH/import can clear a veto or write runtime eligibility.

**Unfinished-apply compensation:** apply_phase distinguishes applying, abort_required, aborting and recovery_required from idle. For an applying attempt, a newer disable, failed forward precondition, cancellation, terminal apply failure or apply deadline marks abort_required, stops forward writes and keeps the gate closed. Another disable preserves an existing compensation phase/deadlines and never clears recovery_required. The owner may call abort directly from applying on a recorded terminal failure/deadline; no undefined cancellation authority is needed. The existing approval permits only its exact abort_plan until abort_until with current controller scope and an unrevoked approval (disabling the preparer or approver does not stop it; OQ-GW-9); continuously held abort-source protection survives a scope PATCH/protection-reconciler outage without a new-adoption readiness check, provided there is no known protection loss; forward expiry/newer disables do not cancel this narrow compensation, but approval revocation or lost controller scope does. Runtime source IDs and a durable bounded per-object UID/resourceVersion/write journal support idempotent abort and fenced takeover; settle outstanding writes and restore only approved resources, deleting only matching attempt-owned creations. Abort calls are bound to the current attempt/approval/digest/epoch; complete_abort requires phase=aborting and fresh complete restored-deployment observations before ending the attempt and reopening old unaffected pins. Advance the runtime generation, retain all newer security revisions/vetoes and invalidations, and never revive closed contexts. A no-prior-pair enrollment abort remains unconfigured/closed. Nonretryable failed/missing/conflicting compensation, revoked approval, lost controller scope or exhausted abort_until marks recovery_required; transient errors retry only within the original window. That phase permits no writes under old authority. Design §4.2 is normative; this is not arbitrary rollback authority.

**Recovery supersession:** a new gateway_apply preparation names supersedes_attempt_id. Before finalization a current scoped owner fences/quiesces prior writers and settles outstanding requests, then captures exact live inventory, failed-attempt revision/journal digest and all unresolved cleanup obligations in recovery_snapshot_digest; unknown ownership/in-flight writes block, not force overwrite. The new security_admin approval binds that snapshot, current security revisions, inherited cleanup, fresh authority/deadlines and an explicit abort target. Only its begin may CAS-replace that recovery_required attempt under a new epoch, mark the predecessor superseded and inherit every unresolved journal obligation, including older creations absent from the new plan. Ordinary begin remains idle-only, registry_only cannot supersede, and stale inventory/old owner/completion replay rejects. The audit sink endpoint, protocol and TLS trust or credential reference are instance deployment configuration, not a tenant secret namespace; the row holds only audit_sink_config_digest and audit_sink_validated_at, and observed sink health is a metric and health signal, not a revisioned row. A sink configuration change takes effect only on restart and first emits a sink-changed event to the old sink, plus an audit event. The sink receives an append-only, hash-chained JSONL stream over syslog-over-TLS or OTLP logs: one chain per instance, where AuditEvent.sequence is assigned in the same transaction and strictly increases, prev_hash links each event to the previous one and the chain head lives in the database (OQ-TM-12). Still open: the sink TLS trust settings and alert routing.

**Policy revisions:** dependency_revisions is a typed immutable set of entity-kind/ID/revision references. WIF snapshots tenant/resource assignment, chosen source/binding, grant and optional service. Human snapshots assignment, HumanAccessPolicy and client or active pinned origin configuration; human_session additionally snapshots its route version and current stable origin/route security revisions. A disable/re-enable cycle cannot revive old evidence. Staging, observation sequence, operational limits and a bundle-only pointer change are not authorization dependencies. Activation supersedes only dependencies actually changed; unchanged route contexts remain valid subject to the runtime gate. Current action rules, provider/authentication epochs, session or native-family validity remain live checks. No fake WIF grant or missing/contradictory dependency/profile exemption.

**One-time state:** store keyed hashes of flow cookies/session tickets/codes/refresh tokens, not plaintext secrets. Only an attempt opting into skyoauth_refresh_request_id stores an authenticated-encrypted issued-response envelope for <=30 seconds under a separate protected key, excluded from exports/logs. Plain refresh has all retry fields null and ordinary consumed-token replay revocation. An extension attempt retains its correlation/deadline metadata after envelope purge; receipt loss must not look like plain rotation. Invalid supplied IDs are rejected, not silently omitted, and replay cannot add/remove an ID to switch paths. Distinct app/native bindings include origin and flow kind; HumanAuthentication links credentials to monotonic provider/tenant epochs. A native authentication/client/audience tuple has at most one refresh family, resolved by live check from signed authentication/client_id/audience and required to be live. HumanAccessPolicy refresh fields apply only to native clients: defaults 12h/1h, explicit maxima 7d/24h within stricter assurance/instance limits. Snapshot approved absolute/idle limits; increases require a new browser-approved family and cannot extend existing state, while tightening permanently narrows/revokes affected families and is enforced on refresh/live checks. Required refresh families have immutable absolute and bounded idle deadlines, unique generation/hash, atomic consume/replace and whole-family replay revocation except opted-in bounded exact retries under design §5.2.2; HumanAuthentication expires at the approved assurance/family bound, not the access token's 300-second bound. No rotation extends auth_time/absolute lifetime. Replay uniqueness spans grants/replicas through exp plus skew and digest-key rotation. Restore preserves consumption or quarantines issuance; config import does not restore it.

**Provider pointer/enrollment:** TenantLoginState is authoritative; HumanProvider has no writable active flag. M1b's guarded transition is the sole pointer/epoch writer and atomically sets enrollment_hold for switch/rollback. Its deliberate compromise transition advances only auth_generation, per tenant and revision-checked, without a provider change (OQ-TM-14). A callback rechecks generation, hold and HumanEnrollmentPolicy in the principal/link transaction. preprovisioned is default; explicit auto_create creates one new zero-privilege principal/link for a previously unseen exact subject, never email-merges or replaces disabled identities. Only explicit provider/generation/revision-bound enrollment-resume clears a migration hold. Credential-only rotation of the unchanged semantic provider/client tuple has a separate revision-checked path and does not advance auth epochs.

**Stream state:** SessionContinuation is created only from a still-valid internal assertion for a stream-capable action. Uniqueness of admitting assertion jti prevents multiple contexts; exact same-checker retry can return the existing context without lease extension. It binds all fields listed above and active origin/route/policy/action versions; it is not a bearer capability. Rechecks require the same authenticated checker and exact context/nonce, current session/epochs/authorization, route-runtime eligibility and backend RBAC. A renewal after the last authorized_until denies, even if the session remains live. A successful lease follows route/action limits: default/critical <=15 seconds; explicit noncritical read-only ceiling <=300 seconds, within one-hour context, session/authentication and applicable observation deadlines. Temporary unavailable grants no new lease and does not close state; terminal denial does. Same-checker batches preserve per-item atomic renewals, not batch-wide authorization. Origin/instance capacity policies govern only admission; lowering them leaves existing live contexts valid. No idle touch, new request, resource change or post-expiry resurrection. close-session atomically sets closed_at/releases occupancy exactly once without requiring live user evidence; matching retries succeed and closed contexts never renew. Unknown/wrong-checker/nonce/context close does not mutate another stream. Crash or lost close retains occupancy only until last lease expiry, independent of cleanup scheduling. Retain bounded close-retry identity and admission-jti tombstones through assertion expiry plus skew; restart requires fresh admission. Internal key disable or verified unpromoted-standby use denies. Capacity wire distinctions and bounded retry budgets follow design §6.1.1.

**Key separation:** public access keys and internal assertion keys have disjoint kid namespaces/trust sets. Internal keys belong to deployment signer groups and are shared only by authorized replicas in that group, not generated per replica. Instance security_admin enrolls/distributes them; replicas cannot self-register. Publish before use, cache freshness <=60s with no stale-on-error, activate_after >= publication + maximum cache window + skew, and readiness gates key loading/publication/activation. New group replicas reuse an active kid; unknown kid gets bounded single-flight fixed-endpoint refetch, then deny. signing_state distinguishes active/standby/retired issuance roles from verification status: standby public material is prepublished, but private material is unavailable to normal auth replicas until audited promotion. Live checks/admission/rechecks reject cryptographically valid evidence from an unpromoted standby and raise a bounded alert; offline verification alone cannot enforce that authoritative-state tripwire. Normal retirement of a previously promoted key retains its documented overlap. Production commissioning/rotation completion requires active plus eligible standby; emergency clean promotion may run in alerted degraded redundancy while replenishing. No eligible unaffected standby means fail closed, not maturity waiver or compromised fallback. Keep key status/provenance through dependent continuation deadlines. Design §6.2 is the key lifecycle contract.

## 10. Definitions of done

**Protocol:** explicit standard/private grant distinction and private credential typing, selectors/defaults/binding selection/replay/constraints; profile-specific verification without upstream-provider configuration or subject-prefix exemptions.

**WIF:** authorized discovery/uploaded-key/TokenReview enrollment, generated stable selectors and direct/delegated service access within instance audience assignments. Secretless GitHub/K8s API calls and correct renewal modes; impersonation not required.

**Gateway:** fail-closed bearer M2; M3 consumes browser credentials, binds exact request/audience and uses active immutable route pins. Named approval/scoped admission/controller/isolated observer enforce deployment, with distinct bounded stale-observation and known-mismatch behavior. Local internal signer/standby tripwire, bounded stream lifecycle and explicit release; no rewrites/rematching, body proxy or backend-RBAC bypass.

**TypeScript SPA:** packaged @skyoauth/client is browser/framework-neutral, not Node health/workload code; memory-only session/CSRF, strict same-origin transport, no OAuth-token getter and no Node/framework core dependencies. Real-browser/package/type/adapter tests include distinct capacity/infrastructure errors, one bounded orphan-recovery retry versus finite shared retries, no login on503, and backend slot release on cancellation.

**Rust CLI:** reusable packaged skyoauth-client works in an independent CLI with PKCE/system browser/loopback, request comparison/explicit approval and required rotating refresh under the 300-second access cap. It always sends the optional retry ID, while generic OAuth clients can refresh without it. Test renewal/replay/revocation and secure persistent or explicit memory-only storage. Thin executable, no server/database dependency or unsafe fallback.

**Administration:** M1a workload provisioning via portable workstation operator/local recovery transport (the library verifies) precedes M2; M1b human provisioning/transition precedes M3. Independent key custody/roles/recovery, exclusive semantic transitions, safe credential rotation, exact deployment approval and enrollment holds cannot be bypassed by upstream identities/imports. Staging, polling and capacity-only changes do not mutate active authorization. Disabled-only impersonation preservation needs no active-mode machinery.

**Migration:** only affected human configuration/authentication state changes through guarded commits. Prebuilt artifacts, audiences/actions/checkers, origin/route/bundle versions and capacity policies, clients/human policies, WIF sources/keysets/bindings/grants/dormant status, issuer keys and effective WIF decisions stay stable; consumed state never revives. Runtime observations refresh independently and cannot be restored as permission.

**Security:** every credential traces to an explicit verified profile and complete policy/authentication provenance, canonical resource tenant and backend RBAC. Revocation/race limits are honest. All unconditional A01–A64 are demonstrable, including login-CSRF/redirect/linking defenses.

Renewable downstream TLS binds an approved reference/profile/writer, not observed leaf/resourceVersion: independently verified old/new overlap is bounded without gate closure/reapproval or age reset, confirmed invalid/unaccounted current or served material denies terminally; missing/late convergence is unavailable without renewal. Fresh complete current-candidate proof under the unchanged contract may clear only the TLS blocker/reset the bounded candidate state under a new sequence, never sample ages or closed contexts. Invalid issuances consume no accepted slot. Exact-mode Secrets instead rotate by staged frozen new reference and scheduled approved gateway_apply, retaining a usable guarded abort source; no in-place renewal or validity waiver. Global UID-keyed credential holds have scoped admin/provisioner views with foreign reasons opaque; only zero-hold CAS sealing plus fenced guard acknowledgement authorizes exact UID/RV/principal deletion. Retiring UIDs cannot gain new holds and unknown state remains protected. security_admin registers the deployed scope tuple; the service verifies it, infrastructure owns whole-namespace denial and the maximum writer envelope, and the reconciler changes only bounded service-approved live entries under a monotonic mutation guard. A non-referenceable cert-manager temporary-key class has fixed creator/owner/marker CREATE/DELETE rights and no UPDATE/reclassification; test cleanup through repeated issuance. Namespace/parameter reservations stay exclusive while disabled; same-ID PATCH preserves verified maintenance until candidate handoff, and disable drains via move-away/retirement before authenticated decommission releases reservations. Continuously protected same-consumer/contract holds keep their proofs during pending PATCH, after verified same-ID cutover and through protection-reconciler outage for compensation and inherited recovery. Cutover requires continuous compatible coverage, rejects prior-revision acknowledgements and requires current-revision evidence for new adoption. Known protection loss invalidates the proof. Deadlines do not extend. Untracked invalid staging uses metadata registration plus the same sealed cleanup, never a bypass. Scoped redacted admin reads expose attempt IDs/revisions/reasons/deadlines for cancel/recovery without controller access; a newer disable/forward expiry after begin triggers abort/reobserve, never restoring security state. Known out-of-plan mismatch closes immediately with terminal rechecks and no stale allowance. Sole-writer GitOps cost, >=2 fenced controllers, fixed mTLS observer, poll<=10s/stale30s/max300s and cluster-admin boundary remain explicit. |
